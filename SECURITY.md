
# Security Policy

## Supported versions

Only the latest tagged minor release is intended to receive security fixes during pre-1.0 development.

## Reporting a vulnerability

Do not open a public issue. Use GitHub private vulnerability reporting after the repository owner enables it, or the private security contact configured by the maintainer. Include affected version, impact, reproduction, evidence and suggested mitigation. Do not include real customer data.

## Response targets

Maintainers should acknowledge credible reports within three business days, triage severity, coordinate remediation and publish an advisory when appropriate. These are project targets, not a warranty.

## Security boundaries

v0.8 is a production foundation and controlled-pilot candidate, not unrestricted production GA. Review `docs/security/THREAT_MODEL.md` and `docs/operations/PRODUCTION_READINESS_CHECKLIST.md`.
