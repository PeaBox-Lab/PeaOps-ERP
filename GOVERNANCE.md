# Project Governance

PeaOps uses maintainer-led, transparent governance during pre-1.0 development.

- Maintainers review roadmap, architecture, releases and community conduct.
- Material changes begin with an issue or proposal and explicit acceptance criteria.
- Two approvals are recommended for security, accounting, migration and data-integrity changes.
- Security fixes may use private coordination before disclosure.
- Release notes identify breaking changes, migrations, known limitations and validation evidence.
- Governance will evolve as the contributor community grows.
