# Support and Service Desk Guide

## Triage data

Collect product version, company, user role, document type/number, endpoint/action, timestamp, status, validation message and whether the action used an idempotency key. Never request passwords or secrets.

## Triage order

1. Confirm service health and version.
2. Determine whether issue is validation, configuration, data, authorization roadmap gap, or defect.
3. Check document status and integration events.
4. Check posting profiles, number sequences, inventory balances and periods.
5. Reproduce safely in a test company.
6. Escalate with concise evidence.

Do not directly edit database records to fix business transactions.
